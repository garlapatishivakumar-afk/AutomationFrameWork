# V7.1 Engineering Notes

## Scope
This document tracks incremental V7.1 work completed after V7.0 baseline validation.

## What Changed
- Replaced V7 orchestrator runtime use of minimal repository model with real repository scan/index flow via FrameworkIndexService.
- Added deterministic repository snapshot generation with file hashes and snapshot hash.
- Added centralized protected-file policy shared by planner, implementation engine, and framework file modifier.
- Updated planner to mark protected targets directly in FilePlan and enforce CREATE confidence floor.
- Added structured human review question objects when planner cannot safely proceed.
- Added transactional implementation behavior for real file writes (opt-in path), hash verification, rollback, and unexpected-change detection.
- Added guarded FrameworkFileModifier path so protected files cannot be modified even when called directly.
- Updated V7 acceptance criteria C7/C8/C9/C16/C17 to use runtime evidence instead of class-existence checks.

## What Is Real
- Real repository scan is executed for orchestrator context selection.
- Real repository snapshot (paths + SHA-256 + deterministic snapshot hash).
- Real file create/extend operations when applyFileSystemChanges is enabled.
- Real rollback verification with hash comparison in transactional path.

## What Remains Simulated
- Dry-run orchestration still skips live build/test stages (S8-S12) by design.
- Token/credit/cost telemetry remains NOT_AVAILABLE without provider-level usage signals.

## Safety Guarantees Verified by Tests
- Protected files (including Hooks.cs and project/config artifacts) are blocked by authoritative policy.
- Protected file attempts create a single HumanReviewRequired record.
- FrameworkFileModifier direct path cannot bypass policy.
- Transaction rollback restores prior content when later file operation fails.
- Repository snapshot hash is deterministic for identical repository state.

## Current Limitations
- Self-healing strategies are deterministic and intentionally limited to safe categories.
- Questionary is in-memory model level; UI workflow remains pending.
- Full behavioral acceptance for build/test-failure scenarios requires live non-dry runs.
